# 설치, 오프라인, 업데이트

HTTPS 또는 localhost에서 브라우저의 앱 설치 기능을 사용할 수 있다. Android/iOS 실제 설치와 휴대전화 인수는 F080에서 별도로 확인한다. 일반 HTTP LAN 주소에서는 서비스 워커를 사용할 수 없다.

서비스 워커는 빌드에 포함된 HTML, JS, CSS, manifest와 아이콘만 precache한다. `/api/`는 fetch 이벤트에서 즉시 제외한다. 개인 데이터, 응답 본문, 연결 비밀, 읽기 상태는 CacheStorage에 쓰지 않는다. 브라우저 디스크에 저장하는 개인 편집 초안은 사용자가 명시적으로 켜는 기존 24시간 복구 설정에 한정한다. 공용 기기에서는 복구 설정을 켜지 않는다.

열린 화면은 연결이 끊겨도 메모리 안의 초안을 유지한다. 서버 저장에 실패하면 저장 완료로 표시하지 않는다. 새로고침하면 공개 앱 화면만 복구하며 개인 데이터를 복원하지 않는다. 연결 복귀 시 활성 서버 조회가 갱신되고, 편집 저장은 revision 충돌 검사를 계속 적용한다.

새 서비스 워커는 대기한다. 사용자에게 업데이트 버튼을 표시하며, 편집 초안이나 열린 편집/빠른 기록 폼이 있으면 적용 버튼을 막는다. 명시적 적용 후에만 새 워커를 활성화하고 새로고침한다. 다른 열린 탭의 이전 공개 청크를 위해 직전 앱 캐시 한 개를 추가 보관한다. 다음 업데이트에서는 더 오래된 앱 캐시를 삭제한다. 모든 보관본은 공개 파일만 포함한다. 업데이트 실패는 기존 워커와 앱을 유지한다.

세션 만료는 편집 폼을 메모리에서 유지하면서 작업 공간을 숨기고 modal을 닫아 로그인 화면에 초점을 준다. 재로그인 뒤 폼을 다시 열고 입력을 복구한다. 로그아웃은 폼과 개인 query cache를 제거하고, opt-in 초안도 기존 logout 처리로 삭제한다. 브라우저 프로필에 접근 가능한 사람에 대한 디스크 암호화는 운영 체제의 책임이다.

자동 검증: `web/e2e/pwa.spec.ts`, `web/e2e/auth.spec.ts`. 업데이트 리허설은 다른 서비스 워커 script URL을 등록해 브라우저의 실제 waiting/activate/controllerchange 경로를 검사한다. 서로 다른 실제 배포 버전의 공인 HTTPS 인수와 구분한다.

AGPL 소스 제공 링크는 로그인과 대시보드 하단에 표시한다. 기본 링크는 공개 작업 브랜치이며, 릴리스 빌드는 `VITE_SOURCE_REF`에 검토한 commit을 넣어 해당 소스를 가리킨다. 배포자는 수정본의 전체 대응 소스를 함께 제공해야 한다.
